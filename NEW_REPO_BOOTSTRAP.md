# `sector-in-brief-data` — Bootstrap Brief

Drop this file into the root of the new `sector-in-brief-data` repo as `BOOTSTRAP.md` (or paste into the first message of the Claude Code session). It is the self-contained context a fresh agent needs to start work without having to re-derive everything.

---

## What this repo is

The producer of the dashboard-facing data artifact consumed by `UrbanInstitute/sector-in-brief` (the Shiny app). It reads canonical NCCS BMF + core + IRS SOI 990-PF + DAF e-file inputs from S3, applies per-panel aggregations, and publishes vintage-tagged parquet to `s3://nccsdata/sector-in-brief/vYYYY.MM/`.

It **replaces** `UrbanInstitute/nccs-dataexplorer-data`, which is being archived after parity is confirmed. See [[0010-sector-in-brief-data-replaces-dataexplorer-data]] in `../nccs-contracts/decisions/` for the full rationale — read it first.

This is **not** a generic explorer. There is exactly one consumer (the sector-in-brief Shiny dashboard). A separate dataexplorer API surface exists and is governed by [[0008-modernize-dataexplorer-api]]; that pipeline is **out of scope** for this repo.

## Non-negotiables

These are the things the old repo got wrong; do not repeat them.

1. **No hardcoded relative paths in R code.** All paths (S3 keys, local fixture roots, output destinations) come from `config.yml` via `read_config()`. The pipeline must be runnable from the repo root, no `setwd()` dance, no "must be run from the parent directory" footgun.

2. **`.gitattributes` from commit one:** `* text=auto eol=lf`. On first clone, also `git config core.autocrlf input`. This avoids the 16-file CRLF mirage that plagued the old repo.

3. **No vendored C++.** No `rapidxml-1.13/`. If a fast XML path is ever needed, justify it in an ADR first.

4. **No scratch/abandoned scripts in `R/`.** Benchmarks and spikes live in a branch or a gist, not in the main tree.

5. **Schema discipline.** Every output parquet uses the canonical dimension column names and types (see "Output contract" below). No `TAX_YEAR` in one file and `Tax Year` in another. No `Size` as `double` in one file and `int32` in another. The data dictionary is derived from the actual schemas, not hand-maintained.

6. **Manifest per vintage.** Every published vintage drops `_manifest.json` alongside the parquets. No silent overwrites of `latest/` without a manifest entry.

7. **Pure derivation functions, tested.** The four dimension derivations and EIN helpers are tested against fixtures. The old repo had these inline in `dplyr::case_when` chains repeated across multiple scripts; consolidate to one definition.

## Output contract (target schema)

Every output parquet has these dimension columns (exact strings, must match `R/options_nogeo.R` in the dashboard):

| column | type | notes |
|---|---|---|
| `Organization Type` | `string` | from `derive_organization_type(subsection_code, nteev2_org_type)`; panel-restricted values per `options_nogeo.R` |
| `Subsector` | `string` | `substr(nteev2, 1, 3)` — 12 NTEE majors (ART, EDU, HEL, HMS, IFA, PSB, REL, MMB, UNI, HOS, ENV, UNU) |
| `Size` | `int32` | ordinal 0–6 expense-band code |
| `Census Region` | `string` | derived from state abbr |
| `Census State` | `string` | 2-letter postal code |
| `Census County` | `string` | county name |
| `Metro/Micro Area` | `string` | CBSA name; NA if no CBSA |

Plus a single year column **named `Year`, typed `int32`**, in every panel that has a temporal dimension. (The old pipeline had `Year` in one file, `Tax Year` in others, `TAX_YEAR` in `pf_pri`. Fix once.)

**Per-panel files and their metric columns:**

| file | year range | metric columns | dashboard panels (per `data_server_args.R`) |
|---|---|---|---|
| `number_nonprofits.parquet` | 1989–2024 | `Number of Nonprofits: int32` | Numbers |
| `finances.parquet` | 1989–2021 | `Total Assets, Total Revenues, Total Expenses, Total Benefits: double` | Assets / Revenues / Expenses / Benefits |
| `gov_grants.parquet` | 1989–2021 | `Total Government Grants: double` | Government Grants (wire it — currently unwired upstream) |
| `pf_grants.parquet` | 1989–2023 | `Total Contributions: double` | PF Grants |
| `pf_pri.parquet` | 1989–2023 | `Total PRI: double` (rename from `PRI_TOTAL`) | PRI (wire it) |
| `daf.parquet` | 2020–2023 | `Number of DAFs, Total Contributions, Total Grants, Total Value, Has DAF: double` | all 5 DAF panels |

**Dimension files** (republished each vintage):

- `nested_geographies.csv` — `Census State, Census County, Metro/Micro Area, Census Region`.
- `data_dictionary.parquet` — one row per (file, column) with `type`, `description`, `derivation_source`. Replaces `panel_dd.csv` and `data_dictionary.xlsx`.

## BMF input translation

Sole BMF input: `s3://nccsdata/geocoding/bmf-master/merged/bmf_master_geocoded.parquet` ([[bmf-master-geocoded]]).

`read_bmf()` returns a tibble/Arrow table with the pipeline's canonical column names. Translation table:

| canonical name | source column | how |
|---|---|---|
| `EIN2` | `ein` | `derive_ein2(ein)` |
| `NTEEV2` | `nteev2` | rename |
| `BMF_SUBSECTION_CODE` | `subsection_code` | rename, cast to integer |
| `F990_TOTAL_ASSETS_RECENT` | `asset_amount` | rename, cast to numeric |
| `CENSUS_STATE_ABBR` | `geo_state_abbr` | rename |
| `CENSUS_COUNTY_NAME` | `geo_county` | rename |
| `CENSUS_CBSA_NAME` | *(derive)* | join via `inst/lookups/cbsa_crosswalk.parquet` on (state, county); NA on miss |
| `NCCS_LEVEL_1` | `nteev2_org_type` + `foundation_code` | derive charity-vs-PF flag — confirm the rule against the old `01_bmf_data.R` `case_when` chain |
| `ORG_YEAR_FIRST` | `first_year_in_bmf` | rename |
| `ORG_YEAR_LAST` | `last_vintage_ym` | parse `YYYY-MM` → integer year |

`read_bmf()` is the **only** function that knows about new-BMF column names. Panel builders consume the canonical names.

## Derivation functions to port (verbatim from old repo)

From `nccs-dataexplorer-data` origin/main, the following `case_when` chains live inline in `R/01_bmf_data.R` and `R/10_api_data.R` (duplicated, Title Case vs SCREAMING_SNAKE). Lift them into one definition each:

- `derive_census_region(state_abbr)` — returns "Northeast" / "Midwest" / "South" / "West". State-abbr lists are at `R/01_bmf_data.R:17-20` in old repo.
- `derive_size(total_expenses)` — returns ordinal 0–6 (old code used `F990_TOTAL_ASSETS_RECENT` in `01_bmf_data.R` but the dashboard's `R/options_nogeo.R` documents the bands as expense-based; **confirm which is right** with the contract before locking it in — this is a known inconsistency between the old pipeline and the dashboard's documented semantics).
- `derive_organization_type(subsection_code, nccs_level_1)` — full mapping at `R/01_bmf_data.R:33-43`.
- `derive_subsector(nteev2)` — `substr(nteev2, 1, 3)`.
- `format_ein(ein)`, `derive_ein2(ein)` — already extracted in old repo as `R/format_ein.R` after rename; lift as-is.

Each gets a `tests/testthat/test-*.R` with at least: known-good inputs, NA handling, edge cases (e.g. AK/HI for region, 0/NA for size).

## S3 prefix migration (do this before publishing the first vintage)

Per ADR 0010 §"Canonical output prefix":

1. Server-side copy the existing `s3://nccsdata/sector-in-brief/*` (16 files, 2024-09) to `s3://nccs-data-archive/superseded/sector-in-brief-2024-09/`, then delete from the working bucket. **Confirm with the user before deleting.**
2. Server-side copy `s3://nccsdata/dataexplorer/visuals/` (including `v1.1/`) to `s3://nccs-data-archive/superseded/dataexplorer-visuals-2025-05/`. Leave a `README.txt` tombstone at the working-bucket prefix pointing at `s3://nccsdata/sector-in-brief/latest/`.
3. Only then publish the first vintage to `s3://nccsdata/sector-in-brief/v2026.MM/`.

Use `--profile thiya` for all `aws` CLI calls in this project.

## Clone hygiene (avoid the trap that bit the old repo)

On first clone of `sector-in-brief-data` — and any future clone — run:

```bash
git fetch --all
git config core.autocrlf input
git status -sb              # check actual ahead/behind, not stale-cache
git rev-list --left-right --count origin/main...HEAD
```

The old `nccs-dataexplorer-data` clone was 51 commits behind with a CRLF re-stain that masqueraded as a 16-file modification pile. The `.gitattributes` `* text=auto eol=lf` in this repo prevents the latter; the `git fetch` discipline catches the former.

## What this repo does NOT produce

- **API-side outputs** (`s3://nccsdata/dataexplorer/api/*`). Governed by [[0008-modernize-dataexplorer-api]]. If the API pipeline's R code is still living in `nccs-dataexplorer-data` at archive time, that's an ADR 0008 follow-up — not this repo's problem.
- **Org-grain microdata.** All outputs of this repo are aggregate-grain (no `EIN2` column, except possibly `gov_grants` if a follow-up decision keeps it). Per-EIN consumers go to canonical NCCS artifacts or the API.
- **Raw 990 XML extraction.** The old repo had a `xml_microbenchmark.R` spike for fast 990 XML download. Not in scope here; if revived, that's its own repo (or `nccs-data-efile`).
